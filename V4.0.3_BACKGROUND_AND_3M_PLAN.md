# Envarg OTC Scanner V4.0.3 — implementation and verification checklist

Status: design / not an installable APK. Branch intentionally does not change the working V4.0.2 code.

## Verified current limitations
- Current Java MainActivity runs scans via a WebView Javascript bridge; it does not run a foreground service.
- Current app.js uses POLL_INTERVAL=300000 and validates five-minute source candles.
- Current paper.js settles virtual trades with DURATION=300000 using verified five-minute source quotes.
- Consequently changing only the displayed duration to 180000 would create inaccurate three-minute results. Do not do it.
- Source URL and its relationship to Olymptrade's actual executable OTC quotes remain unverified.
- The app's 100/100 indicator agreement is not a calibrated probability.

## Background mode implementation
1. Introduce a user-initiated Android foreground service with persistent notification and Stop action. Declare appropriate Android permissions/service type; support modern Android versions.
2. Move networking and signal calculations into a headless engine usable by foreground service; do not depend on WebView timers or Activity lifecycle.
3. Use bounded worker concurrency, timeouts, backoff, network availability checks, and durable event ledger.
4. Restore monitoring state on Activity reopening; expose current background status and last successful scan.
5. Respect user stop, Android force-stop, battery optimizations, and OS restrictions. Never promise uninterrupted scanning after force-stop.
6. Signal notifications only; no real-money order placement, Accessibility interaction, or trade execution.
7. Test screen off, app swiped away, offline/online recovery, reboot, battery saver and Android 13+ notification permission.

## Three-minute vs five-minute evaluation
1. Obtain an independently validated feed with timestamps and cadence fine enough to settle three-minute expiries (e.g. one-minute or tick data); verify source against terminal screenshots/time.
2. Add separate virtual ledgers for 3m and 5m with common signals, equivalent entry assumptions, no lookahead, no fake wins on missing data.
3. Use 100+ settled observations per duration as an initial diagnostic, then out-of-sample walk-forward evaluation with confidence intervals.
4. Report by asset, session, direction, payout and feed error rates; avoid misleading 100% confidence claims.
5. Calculate breakeven rate at payout p as 1/(1+p), e.g. 52.63% for 90% payout.
6. Never auto-select a duration based only on in-sample historical performance.

## Extra features
- Start/Stop foreground monitoring, notification controls, connection/feed health and timestamps.
- Duplicated-signal cooldown and configurable minimum observations for asset rankings.
- Loss diagnostics, draw/void counts, payout-aware performance, CSV export and backup.
- Emergency stop and clear explanation that virtual prices may not match execution.

## Release gate
Do not label a build complete until the Android project compiles, apksigner verify succeeds, installation works on a target device, and the 3m and background behaviors are tested.
